# 校园顺风车（微信小程序）

一个面向校园场景的**出行信息发布与查询工具**：学生发布自己的出行计划（出发地、目的地、日期时间、可带人数、费用分摊），其他同学浏览查询并提交同行申请，由发布者自行决定是否同意。

小程序本身**不提供车辆、不提供驾驶服务、不介入交易、不收取任何费用**，只做信息的发布与查询撮合。

技术栈：微信小程序原生 + 云开发（云函数 `trips` + 云数据库），无第三方前端框架、无 npm 前端依赖。

---

## 快速开始

```bash
git clone <repo>
cd campus-carpool
```

1. **配置云环境**（可选，不配也能跑）
   复制 `config.local.example.js` 为 `config.local.js`，填入自己的云环境 ID：

   ```js
   module.exports = { cloudEnv: 'cloud1-xxxxxxxx' };
   ```

   > 不创建这个文件时 `cloudEnv` 为空串，小程序自动退回**本地演示模式**，数据只存本机，不影响启动与功能试用。

2. **配置 AppID**
   `project.config.json` 里的 `appid` 是占位值 `touristappid`。用微信开发者工具打开项目后，在「详情 - 基本信息」里选择自己的 AppID，工具会把它写进本地的 `project.private.config.json`（该文件不入库）。

3. **部署云函数**（走云端时必须）
   右键 `cloudfunctions/trips` → 「上传并部署：云端安装依赖」。首次部署若提示「函数正在创建中」，等 30 秒后重传。

4. **编译运行**
   开发者工具中重新编译。集合（trips / users / joins / verifications / reports / blocks）由云函数首次调用时自动创建，无需手动建表。

## 各功能要点

### 1. 登录与个人资料

- 用微信 `openid` 识别身份，资料只收集一个「姓」（限中文、最多 2 字）和可选头像，其他同学只会看到「林同学」这样的称呼，不会知道全名。
- 头像**只在本人「我的」页展示**，不下发给其他用户、不出现在拼车列表；退出登录只清本机资料，保留 `openid`，已发布的行程、报名与拉黑记录不会丢。

### 2. 学生认证

- 材料支持**学信网截图（可填在线验证码）或学生证照片二选一**，状态流转为 未认证 / 审核中 / 已驳回 / 已认证；审核中或已认证时隐藏表单，避免重复提交。
- 上传前**超过 10MB 直接拦截**，通过后压缩（长边缩至 1600px、质量 60–80%）；提交必须勾选隐私说明，核验完成后照片立即删除，不做留存、不对外展示。

### 3. 发布行程

- 出发地 / 目的地手打即可，下方给常用站点一点即填；日期不能选过去，**上限为今天起 100 年**（客户端 picker + JS 校验 + 云函数服务端校验三道），当天还需校验时间未过。
- 总价与人均自动计算并实时预览（车主不参与分摊）；可设「不限 / 仅限男生 / 仅限女生」，并校验车主自身性别与限制一致，避免男生发出「仅限女生」这种自相矛盾的行程。

### 4. 拼车列表与城市

- 只展示**未发车、且还有座位**的行程，满员行程自动置为 `full` 并从列表过滤；行程卡片显示「剩 N 座」，详情页显示「已结束 / 已满员」。
- 行程带 `city` 字段按城市分区，首页城市胶囊左侧状态点标出该城市有车（绿）/ 无车（红）；线路筛选只在福州校区生效，切到其他城市自动收起并复位筛选条件。

### 5. 定位

- 用**模糊定位**（千米级、区县级精度）解析所在城市，进小程序先用缓存城市渲染、后台定位成功再自动切换；未授权、未配 key、解析失败一律静默退回当前城市，不阻断启动。
- 定位解析出的**区县**用于发布页预填：人在学校所在区县时出发地自动填「福州工商学院（南门）」，人在外地则留空并收起常用站点胶囊、提示手动填写——宁可空着，也不瞎填一个假地点。

### 6. 上车申请

- 流程为**申请 → 发布者同意 → 剩余座位 −1**，同意操作使用数据库事务实现，防止并发下超卖；申请撤回仅允许在「待处理」状态操作，发布者已处理则不可撤回。
- 按行程的 `genderLimit` 做**双端拦截**（客户端与云函数各校验一次），性别不符直接提示「该行程仅限男生/女生乘坐」；同意时按申请人性别自动累加车上男女数，发布者自身性别在发布时计入。

### 7. 我的

- 分为「我的发布」与「我报名的」两个列表，卡片版式统一：第一行起终点（蓝色箭头居中），第二行日期·时间·发布人 + 状态（待同意 / 已同意 / 已结束）。
- 未登录时不请求任何列表数据，直接展示登录引导面板（灰底人形剪影 + 「点击登录」），登录 / 退出后经 `onShow` 自动回流状态。

### 8. 举报与拉黑

- 举报是**站内自建流程**：提交后写入 `reports` 集合，由后台人工核实处理，不会通知对方；后台处置时提供「下架该行程 + 拉黑该用户」形成闭环。
- 拉黑后**双方行程互不可见**、对方不能再申请你的车；黑名单记录行程快照与备注，用于区分同姓用户，可随时在「我的 - 黑名单」解除。

### 9. 云开发架构

- 所有业务走**单个云函数 `trips`**（客户端 21 个 action），首次调用时由入口兜底 `ensureCollections()` 自动创建 6 张集合，全新环境不用手动建表。
- 下发数据统一**剥离 `_openid` / `ownerOpenid` 等身份字段**，举报 / 拉黑通过 `tripId` 反查目标用户，客户端拿不到对方 openid；云端请求失败直接报错，不静默回退本地数据。

### 10. 性能与体验

- 首页高频往返（进详情返回、切 tab）所需的**登录态与城市行程数带 TTL 短缓存**（30s / 60s），写操作主动失效，下拉刷新强制取最新，显著减少云函数调用次数。
- 深色模式全量适配；页面入场动效、按压反馈、毛玻璃条等细节统一，并适配系统的**减弱动效**与**降低透明度**偏好。

## 目录结构

```
campus-carpool/
├── app.js / app.json / app.wxss     小程序入口、全局配置与全局样式

│   └── haptic.js                    触觉反馈封装
├── images/                          tabBar 图标
└── pages/
    ├── index/                       拼车列表（首页）
    ├── detail/                      行程详情、申请、举报与拉黑弹窗

    ├── legal/                       用户协议与隐私政策
    ├── blocks/                      黑名单
    └── city/                        选择城市
```

## 敏感信息说明

仓库中**不包含**以下内容，需要各自在本地补齐：

| 项 | 存放位置 | 是否入库 |
| --- | --- | --- |
| 云环境 ID | `config.local.js` | 否（已 gitignore） |
| AppID | `project.private.config.json` | 否（已 gitignore） |
| 腾讯位置服务 key | 云函数环境变量 `MAP_KEY` | 否（仅存云端） |
| 管理端令牌 | 云函数环境变量 `ADMIN_TOKEN` | 否（仅存云端） |

云函数的管理端接口（`adminListVerifications`、`adminReviewVerification`、`adminSeed`、`adminListReports`、`adminReviewReport`）依赖 `ADMIN_TOKEN`，未配置时这些接口直接禁用。
